四、关键技术约定（改动前必读）

发信内联强制规则：HTML 正文必须以字符串内联传给 mailer.send()， 严禁"写文件再传路径"——原 Coze 方案的教训，mailer.py 会主动拒绝路径形态的正文。

cron 是 UTC：北京时间减 8 小时。23:23 → 23 15 * * *，23:37 → 37 15 * * *。

面板只认 main 分支：pages.yml 的触发分支是 main，本地仓库分支必须保持 main。

期号三处一致：文件名 / 邮件标题 / 邮件主题 必须同含期号，issue_no.py 有自检。

薅羊毛大标题禁止出现具体日期（模板 deals.html.j2 有注释说明）。

LLM 提示词里 JSON 字段说明不要用英文双引号嵌套（会破坏 Python 字符串或 JSON 示例）， 中文语境用「直角引号」。

插件位约定：scripts/core/plugins/<module>.py 暴露 fetch(keyword, limit) -> List[dict]， 然后在 sources.yaml 把 enabled 改 true。

五、协作偏好（用户既定习惯）

改完代码：AI 只整理 commit message，不执行 git commit/push，由用户自己提交。 commit message 按业务功能分段，不附文件名/方法名/框架名。

出方案：先给实现思路，用户对照评价后再动手；推荐选项要附依据。

输出偏好：高精简度、结构化表格、✅/⚠️ 区分、可操作清单。

用户会以截图方式反馈 UI/界面问题，按红框标注定位。

不自动执行破坏性操作（回滚、删除、发布），先问再做。
