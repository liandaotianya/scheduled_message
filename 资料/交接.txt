一、对话起点
用户原话背景：Coze 每天赠送 1500 积分，三个自动任务（长春薅羊毛/AI日报/用户痛点快报）
每天自动执行，近两个月积分经常不够用导致任务失败，问有什么免费执行定时任务的 AI 工具。
讨论结论：任务本质是「定时触发 → 搜索抓取 → LLM 整理 → HTML 邮件」，无人工确认环节，
最适合 GitHub Actions 免费托管。积分焦虑的根源是 LLM 调用走了平台计费池。
二、逐轮讨论与用户决策
第 1 轮：方案选型
- 我给出三条路线：GitHub Actions+免费LLM（最推荐）/ Dify·n8n 自托管 / Make·Zapier 平台类
- 理由：公开仓库 Actions 完全免费；每天有 commit 天然规避 60 天保活暂停；脚本可控可调试
- 用户未反对，沿此路线推进
第 2 轮：是否需要服务器
- 结论：不需要。GitHub 托管临时容器执行，存档靠 commit 回仓库持久化
- 只有三种情况才需要服务器：单次>6小时 / 常驻长连接 / 强反爬平台被 GitHub IP 挡住
- ⚠️ 用户项目里有小红书/知乎类信息源需求，已预判第 3 种情况，预留了插件位
第 3 轮：开发流程澄清
- 用户问是否需要从 GitHub 下载代码给 AI——澄清了沙箱机制：
AI 在云端沙箱写代码 → 用户下载文件 → 建仓推送。起点是空仓库，无下载前置
第 4 轮：改参数与"app"诉求
- 用户问改参数是否只能改代码、能不能有个 app
- 给出三层方案：A 改 config.yaml / B workflow_dispatch 参数面板 / C 真 Web 管理面板
- 建议"先 A+B 落地，跑顺再考虑 C"；用户拍板：直接按中等的做（静态页+GitHub API）
